# Watch Library Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Human-in-the-loop notice:** Task 2 Step 1, Task 3 Step 3, and Task 5's manual signing note are Xcode-GUI-only steps (adding capabilities, adding *new* files with dual target membership) that cannot be automated by an AI agent driving a terminal. A human must perform each, then hand control back.
>
> **Deviation note (recorded during execution):** Task 4 Step 6 was originally marked "manual, human only" on the assumption that touching the native bridge files required another Xcode-only action. It doesn't: `WorkoutSyncModule.swift`/`.m` already have `ClearHiiT` target membership from Task 1, so *editing their existing content* is a plain text edit, not a new-file registration — fully automatable. Only steps that add files Xcode doesn't yet know about (Task 1 Step 5, Task 3 Step 3, Task 2's capability toggle) actually require a human.

**Goal:** Prove a one-way sync pipeline — phone writes a session/folder change, it lands in a shared Core Data + CloudKit store, and the watch app can read and display it — without touching the phone's existing JSON-file persistence or building the real watch UI (that's the next plan, session engine + UI).

**Architecture:** One-way mirror. `src/lib/sessions.ts`'s existing JSON-file storage (`sessions_v2.json` via `expo-file-system`) is untouched and remains the phone's own source of truth. A new native bridge module (`WorkoutSync`, added directly as a file member of the `ClearHiiT` Xcode target — **not** a CocoaPods-autolinked local Expo module, see the deviation note in Task 1) receives the full `SessionsData` JSON from JS after every successful `saveSessions()` call and mirrors it into a Core Data store shared (via dual target membership, not CocoaPods) between `ClearHiiT` and `ClearHiiTWatch Watch App`. `NSPersistentCloudKitContainer` syncs that store to the watch through CloudKit. The watch only ever reads — no merge/conflict logic is needed.

**Tech Stack:** Swift, Core Data, CloudKit (`NSPersistentCloudKitContainer`), React Native's classic native-module bridge (`RCTBridgeModule` via `RCT_EXTERN_MODULE`, not the Expo Modules API — see Task 1's deviation note), Jest (existing JS test setup).

## Global Constraints

- Carried over from `docs/superpowers/plans/2026-07-21-watch-foundation.md`:
  - iOS deployment target `16.4`, watchOS deployment target `10.0`, team `KM666T7T27`.
  - Phone bundle id `com.georgefromgib.hiittimer`; watch bundle id `com.georgefromgib.hiittimer.watchkitapp`.
  - Any `xcodebuild` command **must** use `-workspace ios/ClearHiiT.xcworkspace`, never `-project ios/ClearHiiT.xcodeproj` — this repo integrates CocoaPods and `-project` cannot see the Pods-generated module maps (confirmed the hard way in the foundation plan).
  - The `ClearHiiTWatch Watch App` target uses a `PBXFileSystemSynchronizedRootGroup`: any file dropped into `ios/ClearHiiTWatch Watch App/` is auto-added to that target with no `project.pbxproj` edit needed. The `ClearHiiT` target does **not** use synchronized groups — adding files to it always requires a manual Xcode "Add Files…" step.
  - Do not run `npx expo prebuild --clean` — this repo's `ios/` is hand-maintained and tracked in git, not purely CNG-regenerated.
- New for this plan:
  - CloudKit container identifier: `iCloud.com.georgefromgib.hiittimer` (standard `iCloud.` + primary bundle id convention).
  - The bridge module is added as a **plain file member of the `ClearHiiT` target**, not a CocoaPods-autolinked local Expo module — confirmed via `ios/Pods/Target Support Files/Pods-ClearHiiT/ExpoModulesProvider.swift`, which is auto-generated by scanning installed **pods** only, so a manually-added file using the Expo Modules API (`Module` class) would never be discovered. The classic `RCTBridgeModule` mechanism (`RCT_EXTERN_MODULE` Objective-C macro + Objective-C runtime introspection) has no such generated-file dependency and works regardless of which target a class is compiled into.
  - Do not adopt Expo's SDK 56 "inline modules" experiment (`expo.experiments.inlineModules`) for this bridge: it requires running `npx expo prebuild` to take effect, which conflicts with the "don't run prebuild" constraint above, and its docs do not confirm it won't disturb the manually-added watch target.
  - Explicitly out of scope for this plan: the real Standard/Treadmill watch UI, the session-running engine, HealthKit, and any merge/conflict handling (the watch never writes). Those are later plans.
  - No new Xcode test target (XCTest) is created in this plan — there is no existing native test target in this repo, and the Core Data logic here is a thin CRUD layer. Native verification uses the same build+install+screenshot method the foundation plan established and its review endorsed as an appropriate substitute for genuine Xcode-scaffolding work. JS-side logic (JSON encode/decode boundary, the `saveSessions` → bridge call) gets real Jest unit tests, consistent with the existing `src/lib/__tests__/` conventions.
  - CloudKit sync propagation between two simulators cannot be fully automated (it requires a real, signed-in-on-both-simulators iCloud account and has non-deterministic propagation delay). Task 5 describes the best available manual verification and flags this limitation explicitly rather than pretending it's automatable.

```swift
// ios/Shared/WorkoutStore.swift
import CoreData

final class WorkoutStore {
  static let shared = WorkoutStore()

  let container: NSPersistentCloudKitContainer

  private init() {
    container = NSPersistentCloudKitContainer(name: "WorkoutModel")
    guard let description = container.persistentStoreDescriptions.first else {
      fatalError("WorkoutStore: no persistent store description found")
    }
    description.setOption(true as NSNumber, forKey: NSPersistentHistoryTrackingKey)
    description.cloudKitContainerOptions = NSPersistentCloudKitContainerOptions(
      containerIdentifier: "iCloud.com.georgefromgib.hiittimer"
    )
    container.loadPersistentStores { _, error in
      if let error = error {
        fatalError("WorkoutStore: failed to load persistent store: \(error)")
      }
    }
    container.viewContext.automaticallyMergesChangesFromParent = true
  }

  func applySessionsDataJSON(_ json: String) {
    let context = container.newBackgroundContext()
    context.perform {
      guard let data = json.data(using: .utf8),
            let decoded = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
            let folders = decoded["folders"] as? [[String: Any]],
            let sessions = decoded["sessions"] as? [[String: Any]] else {
        print("[WorkoutStore] applySessionsDataJSON: failed to parse JSON")
        return
      }

      for folder in folders {
        guard let id = folder["id"] as? String else { continue }
        let record = self.fetchOrCreate(entityName: "FolderRecord", id: id, in: context)
        record.setValue(folder["name"] as? String, forKey: "name")
        record.setValue(folder["icon"] as? String, forKey: "icon")
        if let createdAt = folder["createdAt"] as? Double {
          record.setValue(Date(timeIntervalSince1970: createdAt / 1000), forKey: "createdAt")
        }
        if let folderJSON = try? JSONSerialization.data(withJSONObject: folder),
           let folderJSONString = String(data: folderJSON, encoding: .utf8) {
          record.setValue(folderJSONString, forKey: "json")
        }
      }

      for session in sessions {
        guard let id = session["id"] as? String, let folderId = session["folderId"] as? String else { continue }
        let record = self.fetchOrCreate(entityName: "SessionRecord", id: id, in: context)
        record.setValue(folderId, forKey: "folderId")
        record.setValue(session["name"] as? String, forKey: "name")
        record.setValue(Date(), forKey: "updatedAt")
        if let sessionJSON = try? JSONSerialization.data(withJSONObject: session),
           let sessionJSONString = String(data: sessionJSON, encoding: .utf8) {
          record.setValue(sessionJSONString, forKey: "json")
        }
      }

      do {
        try context.save()
      } catch {
        print("[WorkoutStore] applySessionsDataJSON: save failed: \(error)")
      }
    }
  }

  private func fetchOrCreate(entityName: String, id: String, in context: NSManagedObjectContext) -> NSManagedObject {
    let request = NSFetchRequest<NSManagedObject>(entityName: entityName)
    request.predicate = NSPredicate(format: "id == %@", id)
    request.fetchLimit = 1
    if let existing = try? context.fetch(request).first {
      return existing
    }
    let entity = NSEntityDescription.entity(forEntityName: entityName, in: context)!
    let record = NSManagedObject(entity: entity, insertInto: context)
    record.setValue(id, forKey: "id")
    return record
  }

  func fetchCounts() -> (folders: Int, sessions: Int) {
    let context = container.viewContext
    let folderCount = (try? context.count(for: NSFetchRequest<NSManagedObject>(entityName: "FolderRecord"))) ?? 0
    let sessionCount = (try? context.count(for: NSFetchRequest<NSManagedObject>(entityName: "SessionRecord"))) ?? 0
    return (folderCount, sessionCount)
  }
}
```
